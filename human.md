# Human Notes for Studi

- Use `bun` and `bunx`; do not switch package managers.
- Build the best possible learning experience: one-on-one tutoring, intuition first, short time to aha, and questions that help the learner feel they invented the idea.
- Treat Sparks as the signature interface for learning beyond text: interactive scenes, graphs, code playgrounds, quizzes, flashcards, and future whiteboards.
- Keep the product core simple: auth, chat, Sparks, billing/limits, waitlist, and a single `studi` tutor identity.
- Work test-first when possible, then close the loop with lint, unit tests, Convex tests, build, and browser verification for UI changes.
- Never commit real API keys or copied secrets. Use placeholder env names in docs and rotate any key pasted into chat.
